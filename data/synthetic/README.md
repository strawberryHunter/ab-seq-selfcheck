# Synthetic sequence corpus

Generated by `scripts/make_synthetic_sequences.py`. To regenerate:

```bash
python3 scripts/make_synthetic_sequences.py
```

To only check that the content matches the existing files:

```bash
python3 scripts/make_synthetic_sequences.py --check
```

The generator uses a fixed seed, so the same input always produces the same sequences.

## Data provenance

**Everything is synthetic.** No real therapeutic antibody sequences or records from any specific
germline database were copied. The framework regions are "germline-like" scaffolds: weighted
random residues mimicking the composition commonly seen in V domains, with only the conserved
residues (Cys, Trp, WGxG/FGxG) fixed at set positions. They do not correspond to any real
sequence. These are inputs for regression-testing the annotation logic, not objects of
biological interpretation.

## How it is built

The approach is "insert CDRs into a scaffold." Because the CDR positions are known at the moment
of insertion, the ground-truth CDR coordinates are stored alongside. All VH cases share the same
framework scaffold, and all VL cases share the same VL scaffold. When a CDR length changes, every
downstream anchor shifts (`SYN-VL-002` has a short CDR-L1, so Cys2 lands at position 85), which
verifies that the annotator locates anchors by relative distance rather than by fixed numbering.

### VH coordinate design (1-based linear positions, mimicking Kabat boundaries)

| Region | Position |
|---|---|
| FR1 | 1..21 |
| Conserved Cys (anchor) | 22 |
| FR2a | 23..30 |
| CDR-H1 | 31.. (= Cys22 + 9) |
| Conserved Trp (anchor) | Right after CDR-H1 (typically 36) |
| FR2b | Trp+1 .. Trp+13 |
| CDR-H2 | Trp+14 .. |
| FR3 motif `[RK].[TSAV][IMLFV][STA]` (anchor) | Right after CDR-H2 (typically 66) |
| Rest of FR3 | 21 residues starting at motif+5 |
| Conserved Cys (anchor) | Typically 92 |
| FR3 tail | Cys+1 .. Cys+2 |
| CDR-H3 | Cys+3 .. (= Cys92 + 3) |
| `WGxG` (anchor) | Right after CDR-H3 |
| FR4 | 7 residues after that |

### VL coordinate design

| Region | Position |
|---|---|
| FR1 | 1..22 |
| Conserved Cys (anchor) | 23 |
| CDR-L1 | 24.. (= Cys23 + 1) |
| Conserved Trp (anchor) | Right after CDR-L1 (typically 35) |
| FR2 | Trp+1 .. Trp+14 |
| CDR-L2 (fixed at 7 residues) | Trp+15 .. |
| FR3 | 31 residues right after CDR-L2 |
| Conserved Cys (anchor) | Typically 88 |
| CDR-L3 | Cys+1 .. |
| `FGxG` (anchor) | Right after CDR-L3 |
| FR4 | 7 residues after that |

## Generator self-checks

CDR content is redrawn until the assembled sequence satisfies all of the following. This ensures
that only controlled inputs enter the corpus.

1. The terminal `WGxG` (or `FGxG`) is the **last** match in the sequence, with no opposite-chain
   motif after it — so chain identification is never ambiguous.
2. The anchor is the only Cys within the 15..30 window (16..30 for VL).
3. The **first** Trp after the start of CDR1 is the intended Trp anchor.
4. The **first** FR3 motif match after CDR-H2 start +9 is the intended FR3 anchor (it does not
   match earlier by chance inside CDR-H2).
5. The **first** Cys after the FR3 motif (CDR-L2 for VL) is the intended second Cys anchor.
6. The only liability motifs in each CDR are **those fully contained in the injected fragment**
   — so the tests can assert "this case's CDR liabilities are exactly these."

Cys/Trp/Met/Asn/Asp are excluded from the framework filler alphabet. This keeps the conserved
anchors unique and prevents accidental liabilities in the framework. Cases that need a framework
liability (`SYN-VH-006`) inject it explicitly.

Note: the conserved Trp anchors (Trp36, the Trp of `WGxG`) are by nature oxidation motifs, so the
liability detector reports them as **oxidation sites in the framework**. This is expected
behavior; in real antibodies these Trp residues are usually buried and low-risk.

## Files

- `sequences.json` — the canonical corpus, with ground-truth CDR coordinates and expected values
- `sequences.fasta` — an easy-to-read copy (no ground-truth coordinates)

### `sequences.json` record structure

```
id          sequence ID
chain       "H" | "L"
description description (in Korean)
sequence    amino acid sequence
length      length
notes       list of intentionally injected liabilities
expected
  cdrs      {"CDR-H1": {"start", "end", "seq"}, ...} or null (anchors broken)
            start/end are 1-based, inclusive at both ends
  chain     expected chain or null
  confident whether the annotator should return confident=True
  anchors_broken  whether the anchors are deliberately broken in this case
  length_outlier  whether a CDR length falls outside the normal range in this case
anchors_intended  intended anchor positions (1-based)
```
